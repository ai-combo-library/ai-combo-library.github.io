完整实测报告

engram + ffflow

用户准备一组预设的媒体占位文件和相应配置后，engram 先扫描并分类这些文件，ffflow 再接收其分类文本并执行批处理，返回一份使用了该分类内容的非空批处理文本；这能帮助用户在投入真实设备、外部元数据服务和大批媒体测试前，先判断两个工具能否完成基础接力。

内容与媒体 · 实测通过 · 有使用限制 · 强推荐有实测证据含限制说明
engramffflow
适合谁手上已有媒体占位文件和相应配置，希望先筛查 engram 与 ffflow 基础衔接能力的个人用户或小团队。
不适合谁需要直接连接光学设备、调用外部元数据服务、验证真实媒体成品、大批量处理能力、干净环境安装效果或交互式终端操作的人。
最大的限制需要按工具说明安装本地依赖；建议固定版本后再长期使用。

我们怎么测

使用固定的媒体占位文件和配置运行 engram，将它生成的扫描分类文本交给 ffflow，再检查传入 ffflow 的文本以及 ffflow 返回的批处理文本是否非空。

实际结果

engram 成功生成了非空扫描分类文本，ffflow 确实接收了这份文本并返回非空批处理文本；两项检查全部通过。

实际工作流怎么走

  1. 1. engram：获取原始资料，并把内容交给下一步。
  2. 2. ffflow：接收上一步结果并自动继续处理。

继续补成可长期使用方案要做什么

  1. 固定输入样本和预期输出。
  2. 锁定依赖版本并在干净环境重新执行。
  3. 保留失败原因、产物和复测日期。

本次只用固定生成的媒体占位文件测试了 engram 的本地待导入目录扫描与分类，没有连接光学设备，也没有访问外部元数据服务。测试环境未预设可用的 Rust 工具链，因此临时获取了公开的精简 Rust 工具链和锁定版本的公开依赖。ffflow 使用复制出的只读来源，并增加了非交互、无界面的批处理分支；仅确认其真实批处理解析与 ffmpeg 执行路径得到保留。测试并非在干净环境中进行，也没有覆盖处理规模；其他环境、真实媒体数量及性能均未验证。
Exercises Engram’s local staging-import scan and classification path using deterministic seeded media placeholders; it does not access optical hardware, external metadata services, or execute the downstream tool.；Fetches a public minimal Rust toolchain and locked public crate dependencies because no usable Rust toolchain is assumed in the sandbox.；Stages the read-only source under run_dir and adds a non-interactive headless batch branch, avoiding PTY allocation while retaining ffflow's real batch parser and ffmpeg 自动测试程序 path.
