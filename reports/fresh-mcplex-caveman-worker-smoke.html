完整实测报告

mcplex + caveman

用户把待分析的程序代码和具体分析要求交给 mcplex，由它生成架构分析说明；caveman 接收这份说明并压缩，交付精简版架构分析答复和 token 数量指标，省去用户自行压缩长篇架构说明并另行统计文本用量的步骤。

开发与 Agent · 实测通过 · 有使用限制 · 强推荐有实测证据含限制说明
mcplexcaveman
适合谁适合希望从现有程序代码获得精简架构分析答复，并同时查看 token 数量指标的个人用户和小团队。
不适合谁不适合无法访问公网、使用未覆盖的操作系统或处理器架构，或者要求大规模处理能力及全新环境表现已有验证的用户。
最大的限制需要通过公网下载固定的 mcplex v0.7.1；已覆盖的发布包只有 macOS arm64、macOS x86_64 和 Linux x86_64。此次测试并非在全新环境中完成，处理规模上限以及其他操作系统和处理器架构均未验证。

我们怎么测

先让 mcplex 根据程序代码和分析要求生成架构分析说明，再把这份说明交给 caveman 压缩，最后逐项核对架构说明的传递、精简答复和 token 数量指标。

实际结果

mcplex 与 caveman 均成功运行，caveman 确实使用了 mcplex 生成的架构分析说明；架构说明传递和内容压缩两项检查全部通过。

实际工作流怎么走

  1. 1. mcplex：获取原始资料，并把内容交给下一步。
  2. 2. caveman：生成最终可查看、下载或交付的结果。

继续补成可长期使用方案要做什么

  1. 固定输入样本和预期输出。
  2. 锁定依赖版本并在干净环境重新执行。
  3. 保留失败原因、产物和复测日期。
