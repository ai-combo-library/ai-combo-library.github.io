完整实测报告

plug-n-skills + caveman

用户提供一份待分析的软件项目代码，plug-n-skills 先生成架构分析说明，caveman 再读取这份说明并产出压缩后的说明和词元用量指标；这套组合省去了用户在取得架构说明后手工删减内容并核对篇幅的步骤。

开发与 Agent · 实测通过 · 有使用限制 · 强推荐有实测证据含限制说明
plug-n-skillscaveman
适合谁手上已有软件项目代码，希望先取得架构说明，再将说明压缩并查看词元用量指标的个人用户或小团队。
不适合谁需要分析 Git 提交历史、要求已在全新环境中验证，或需要确认大型项目处理能力的用户。
最大的限制架构分析说明仅包含较为保守的静态探查证据，不包含可选的 Git 历史分析。本次测试并非在全新环境中完成，也没有进行规模测试；其他项目规模和运行环境均未验证。

我们怎么测

用一份实际的软件项目代码运行 plug-n-skills，将其生成的架构分析说明原样交给 caveman，再核对 caveman 是否读取了该说明，并检查压缩后的说明与词元用量指标。

实际结果

plug-n-skills 与 caveman 均成功运行；caveman 确实使用了前者生成的架构分析说明，架构说明传递与内容压缩两项检查均通过，共通过 2 项中的 2 项。

实际工作流怎么走

  1. 1. plug-n-skills：获取原始资料，并把内容交给下一步。
  2. 2. caveman：生成最终可查看、下载或交付的结果。

继续补成可长期使用方案要做什么

  1. 固定输入样本和预期输出。
  2. 锁定依赖版本并在干净环境重新执行。
  3. 保留失败原因、产物和复测日期。
